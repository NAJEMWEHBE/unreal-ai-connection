### Added

Entries listed reverse-chronologically by PR number (newest first).

- **`material_auto_remap` synthetic tool** ([PR #248](https://github.com/NAJEMWEHBE/unreal-ai-connection/pull/248)). Builds a PBR `Material` from a set of UE texture assets (base color / normal / roughness / metallic / ambient occlusion) and assigns it to a level actor's StaticMesh in one call — automating the create-material → add-correctly-typed-TextureSample-per-map → wire-to-output → push-onto-every-slot loop that previously had to be hand-written via `execute_unreal_python`. The natural finisher for `import_mesh` / `import_texture` (first A-track "assembly" tool). Sampler types applied automatically (base sRGB, normal as normal map, rough/metal/AO linear grayscale); optional UV tiling; `/Game/` + injection guards; fails closed on a missing result marker; engine-gated 5.0+. Tool count 106 → 107 (synthetic 34 → 35). +8 pytest cases (521 → 529).
- **`import_mesh` synthetic tool** ([PR #247](https://github.com/NAJEMWEHBE/unreal-ai-connection/pull/247)). Imports a 3D mesh file (`.glb`/`.gltf`/`.fbx`/`.obj`) from disk into the project as StaticMesh asset(s) — filling the gap left by `import_texture` (images only). Drives UE Interchange to a `/Game/` path and returns the **exact** created StaticMesh asset paths by diffing the destination folder before/after, so callers never have to guess Interchange's sub-folder nesting before binding the mesh to an actor (a real friction point hit while iterating Blender→UE). Filesystem + `/Game/` guards, extension allowlist, paths baked via `repr()` (injection-safe), engine-gated 5.0+. `import_materials=False` is honored (Interchange-made material assets are removed post-import; meshes fall back to the engine default). Fails closed if the result marker is missing (no hollow `ok` with empty lists). Class checks use the asset registry (`find_asset_data`), not `load_asset`, to avoid loading every imported asset into memory; both folder diffs guard `does_directory_exist`. Tool count 105 → 106 (synthetic 33 → 34). +11 pytest cases (510 → 521).
- **`execute_unreal_python` / `exec_python_persistent` now capture stdout** ([PR #246](https://github.com/NAJEMWEHBE/unreal-ai-connection/pull/246)). The raw-Python exec tools now return a `stdout` field containing anything the user code `print()`ed plus any traceback — closing the long-standing gap where every result came back `"output": "None"` (UE's `FPythonCommandEx::CommandResult` in ExecuteFile mode returns the last-expr repr, not stdout). Fixed bridge-side (no C++ recompile): the bridge wraps the user code so its stdout/stderr is redirected to a temp file it reads back, then folds the text into `result["stdout"]`. User code is embedded via `repr()` (no re-indentation corruption of multi-line literals) and run against `globals()`, so `exec_python_persistent`'s cross-call state is preserved. On user error the traceback is flushed and the exception re-raised so UE still reports `ok=False`. `unreal.log()`/`log_warning()` still route through `get_log_lines` (LogPython category, not Python stdout). Wrapper uses `builtins.open` (not an unqualified `open` that user globals could shadow) and never binds a `__ucm_reraise` global (pop-in-raise), so nothing leaks into the persistent namespace. +7 pytest cases (503 → 510).
- **`driving-unreal` bundled skill + Widget/UMG recipe + tool-name guard** ([PR #238](https://github.com/NAJEMWEHBE/unreal-ai-connection/pull/238), [PR #240](https://github.com/NAJEMWEHBE/unreal-ai-connection/pull/240)). New auto-discovered skill (`skills/driving-unreal/SKILL.md` + `reference.md`) teaching which MCP tools to chain for common UE workflows (build-a-level, materials, photo→scene, sequencer, asset hygiene, Widget/UMG). `tests/test_skill_tool_refs.py` guards every tool name the skill cites against the bridge catalog so a recipe edit can't reintroduce a phantom name.
- **Prebuilt UE 5.6 binaries — release [`v0.9.1-ue5.6`](https://github.com/NAJEMWEHBE/unreal-ai-connection/releases/tag/v0.9.1-ue5.6)**. ### Changed

Entries listed reverse-chronologically by PR number (newest first).

- **BREAKING — MCP server renamed.** The MCP server name changed from `unreal-claude-mcp` to `unreal-ai-connection`, and the bridge script was renamed `bridge/unreal_claude_mcp_bridge.py` → `bridge/unreal_ai_connection_bridge.py`. **Every existing client must update its `.mcp.json` / config**: change the server key to `unreal-ai-connection` and the bridge path to the new filename. See `docs/setup/` for per-client snippets. The C++ plugin module identity (`UnrealClaudeMCP`) is renamed separately in a follow-up (it requires a UE rebuild); this change is bridge-side + docs only.
- **Bot-review gate hardened across PR #184's six commits** ([PR #184](https://github.com/NAJEMWEHBE/unreal-ai-connection/pull/184)). ## [0.9.1] — 2026-05-23

The `bulk_*_assets` family completion plus the inspect-synthetic round-out. (Tagged `v0.9.1` on 2026-05-23.)

### Added

- **`bulk_duplicate_assets`** ([PR #138](https://github.com/NAJEMWEHBE/unreal-ai-connection/pull/138)). Fourth + final member of the `bulk_*_assets` family. Per-entry `{path, dest_path, new_name?}` mapping. Unlike rename/move, does NOT leave a redirector at the source.
- **`bulk_rename_assets`** ([PR #136](https://github.com/NAJEMWEHBE/unreal-ai-connection/pull/136)). Per-entry `{path, new_name}` mapping. `new_name` validated for slashes/dots (rename_asset is name-only).
- **`bulk_move_assets`** ([PR #133](https://github.com/NAJEMWEHBE/unreal-ai-connection/pull/133)). Flat `paths[]` + single shared `dest_folder`. Mirrors `bulk_delete_assets` shape.
- **`inspect_metasound`** ([PR #135](https://github.com/NAJEMWEHBE/unreal-ai-connection/pull/135)). Accepts both `UMetaSoundSource` (emitter-attached) and `UMetaSoundPatch` (reusable subgraph). Surface-level metadata only; graph-level traversal is deferred.
- **`inspect_material_function`**, **`inspect_audio_bus`**, **`inspect_sound_submix`** (earlier in the milestone). Round out the marker-pattern inspect_* family.
- **`compile_mod_pak_direct`** (cherry-picked from a contributor PR). Bypasses RunUAT entirely by shelling out to UnrealPak.exe directly with a response file. Workaround for Dev Kits in 'installed-build mode' where BuildMod fails on UAT ScriptModules scans.

### Internal

- Tool count: 75 → 80 (+5; one cherry-pick + four net-new synthetics shipped in autopilot).
- pytest cases: 202 → 243 (+41).
- Two LIVE-FOUND bugs fixed mid-milestone: PR #127 (UE 5.7 Python `unreal.Rotator` constructor takes args in struct-memory order, NOT named-property order — positional form was silently scrambling rotations); PR #126 (inspect_* `asset_not_found` error message shape aligned to canonical `<tool>: asset_not_found: <path>`).
